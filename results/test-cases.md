**Фича**: US-3.1 | Главный Экран для Неавторизованных Пользователей
**Источники требований**:
- US-3.1 | Главный Экран для Неавторизованных Пользователей (бизнес-требования, критерии приёмки АС-1…АС-15, вариант использования UC-3.1, альтернативные сценарии 1-9, исключения 1-4)

**Запуск**: `npx playwright test tests/main-screen/non-authorized-user.spec.ts --reporter=list`
**Окружение**: реальный тестовый стенд проекта (`BASE_URL` / `UMBRACO_CMS` из `.env`), без VPN
**Дата прогона**: 2026-11-20
**Итог**: 23 passed / 3 failed (26 тест-кейсов)

**Общее предусловие для всех кейсов**: пользователь не авторизован (статус "Гость"), приложение открыто на главном экране.

**Шаги**: `GET /content/item/{id}?fields=properties[entityTitle,description]`; сверить набор ключей `properties` с запрошенным.
**Ожидаемый результат**: в ответе присутствуют только запрошенные поля.
**Статус**: ✅ passed

### TC-16 (ID 6664): Локализация через заголовок Accept-Language при запросе по id
**Шаги**: `GET /content/item/{id}` с `Accept-Language: en-US`; проверить наличие `cultures` в ответе.
**Ожидаемый результат**: статус 200 OK; `cultures` определён.
**Статус**: ✅ passed

### TC-17 (ID 6675): Фильтрация `filter=contentType:alias`

**Статус**: ✅ passed

**Шаги**: запросить продукты с сортировкой по убыванию даты создания; сверить порядок элементов.
**Ожидаемый результат**: элементы отсортированы по `createDate` по убыванию.
**Статус**: ✅ passed

### TC-20 (ID 19648): `fetch=children` — дочерние элементы узла
**Шаги**: `GET /content?fetch=children:/products`; проверить `total` и типы дочерних элементов (card/loan/deposit).
**Ожидаемый результат**: `total` > 0, типы элементов входят в ожидаемый набор.
**Статус**: ❌ **failed** — `total` вернулся равным 0 (пустой список дочерних элементов).

### TC-21 (ID 19649): `fetch=ancestors` — родительский узел
**Шаги**: `GET /content?fetch=ancestors:{id}`; проверить `total=1` и тип родителя (`products`).
**Ожидаемый результат**: возвращается ровно один элемент — корневой узел продуктов.
**Статус**: ✅ passed

### TC-22 (ID 19650): Пагинация `skip`/`take`
**Шаги**: запросить первую и вторую "страницы" продуктов (`take=3`, `skip=3` для второй); сверить размер страниц и отсутствие пересечения id между ними.
**Ожидаемый результат**: обе страницы ≤ `take` элементов, `total` одинаков, элементы не пересекаются.
**Статус**: ✅ passed

### TC-23 (ID 19651): Параметр `expand` не нарушает структуру ответа
**Шаги**: `GET /content/item/{id}?expand=properties`; проверить обязательные поля продукта.
**Ожидаемый результат**: структура ответа валидна при использовании `expand`.
**Статус**: ✅ passed

### TC-24 (ID 19652): Фильтрация по диапазону `createDate`
**Шаги**: запросить продукты с `filter=createDate>:2020-01-01&filter=createDate<:2030-01-01` (текущий диапазон) и отдельно с диапазоном в будущем (`>2099-01-01`).
**Ожидаемый результат**: текущий диапазон возвращает элементы (> 0), будущий диапазон — пусто.
**Статус**: ❌ **failed** — текущий диапазон вернул 0 элементов вместо ожидаемого непустого списка.

### TC-25 (ID 19653): Preview без валидного Api-Key
**Шаги**: `GET /content/item/{id}` с `Preview: true` и заведомо невалидным `Api-Key`.
**Ожидаемый результат**: статус 401 Unauthorized (согласно описанию Preview-механизма техдокумента: без корректного ключа неопубликованный контент недоступен).
**Статус**: ✅ passed

### TC-26 (ID 6692): Сортировка продуктов по имени
**Шаги**: запросить продукты раздела `/products`, отсортировать имена на клиенте и сравнить с порядком в ответе.
**Ожидаемый результат**: порядок элементов в ответе соответствует алфавитной сортировке по имени.
**Статус**: ✅ passed
