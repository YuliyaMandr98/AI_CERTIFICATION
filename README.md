# AI-сертификация: Микро-делегирование (задание 20)

Демонстрация делегирования QA-задачи агенту (Claude Code) на примере реального
рабочего проекта `qa-api-tests` (Playwright + TypeScript, API-тесты банковского
мобильного приложения). Реальный клиентский репозиторий остаётся в Azure DevOps
проекта и не публикуется — здесь только то, что безопасно показать: персональный
AI-слой (акселератор) + один публичный, не связанный с авторизацией/секретами
тест-файл + результат его реального прогона.

## Что здесь

- **`.claude/`** — персональный AI-слой, установленный на базе
  [innowise-ai/outstaff-accelerator-kit](https://github.com/innowise-ai/outstaff-accelerator-kit)
  поверх wrapper-воркспейса (не внутри клиентского репозитория):
  - `.claude/hooks/git-guard.py` — хук, блокирующий `git push`/`git commit`/
    деструктивные git-команды со стороны агента внутри воркспейса (67 юнит-тестов,
    все зелёные — `python3 .claude/hooks/test_git_guard.py`);
  - `.claude/skills/testing/`, `.claude/skills/doctor/` — установленные скиллы кита
    (doctor — самопроверка сборки: `python3 .claude/skills/doctor/scripts/doctor.py`,
    36 pass / 0 fail на момент установки);
  - `.claude/settings.local.json` — права: COMMIT_POLICY=never, PUSH_POLICY=never
    (коммит и пуш — всегда действие человека, агент только готовит).
- **`tests/main-screen/non-authorized-user.spec.ts`** — реальный тест-файл из
  `qa-api-tests` (фича E-3 «Главный экран для неавторизованных пользователей»:
  публичный контент банка — баннеры, список кредитов/карт/депозитов — без
  авторизации, без секретов и персональных данных).
- **`results/test-cases.md`** — то, что сделал агент: взял 26 тест-кейсов из
  этого файла, реально прогнал их (`npx playwright test ...`) против тестового
  стенда проекта и записал результат по каждому: 23 passed / 3 failed, с деталями
  по упавшим.

## Процесс (что делегировалось агенту)

1. Установить акселератор на wrapper-воркспейс вокруг реального проекта, не
   затрагивая сам клиентский репозиторий (`.claude`/`CLAUDE.md` там уже были в
   `.gitignore` до этой задачи).
2. Взять существующие тест-кейсы одной фичи.
3. Реально прогнать их против стенда.
4. Записать результат (прошло/не прошло) в файл.

Коммит и пуш в этот репозиторий сделаны вручную (человеком), согласно
PUSH_POLICY=never, установленному при онбординге.
