# AI-сертификация: Микро-делегирование (задание 20)

Демонстрация делегирования QA-задачи агенту (Claude Code) на примере реального
рабочего проекта `qa-api-tests` (Playwright + TypeScript, API-тесты банковского
мобильного приложения). Реальный клиентский репозиторий остаётся в Azure DevOps
проекта и не публикуется — здесь только то, что безопасно показать: персональный
AI-слой (акселератор) + один публичный, не связанный с авторизацией/секретами
тест-файл + результат его реального прогона.

## Что здесь

- **`.claude/`** — персональный AI-слой, установленный на базе
  [innowise-ai/outstaff-accelerator-kit](https://github.com/innowise-ai/outstaff-accelerator-kit)
  поверх wrapper-воркспейса (не внутри клиентского репозитория):
  - `.claude/hooks/git-guard.py` — хук, блокирующий `git push`/`git commit`/
    деструктивные git-команды со стороны агента внутри воркспейса (67 юнит-тестов,
    все зелёные — `python3 .claude/hooks/test_git_guard.py`);
  - `.claude/skills/testing/`, `.claude/skills/doctor/` — установленные скиллы кита
    (doctor — самопроверка сборки: `python3 .claude/skills/doctor/scripts/doctor.py`,
    36 pass / 0 fail на момент установки);
  - `.claude/settings.local.json` — права: COMMIT_POLICY=never, PUSH_POLICY=never
    (коммит и пуш — всегда действие человека, агент только готовит).
- **`results/test-cases.md`** — то, что сделал агент: по двум документам с
  требованиями (US-3.1 бизнес-требования + US-3.1 Umbraco Content Delivery API
  техническая реализация) написал 26 тест-кейсов с подробными шагами и ссылкой
  на конкретный пункт требования, автоматизировал их (Playwright + TypeScript),
  реально прогнал против тестового стенда и записал результат по каждому:
  23 passed / 3 failed, с деталями по упавшим.
- **`results/bug-reports.md`** — подробные баг-репорты по 3 упавшим кейсам
  (шаги воспроизведения, ожидаемый/фактический результат, гипотеза о причине,
  severity-кандидат) — черновики для трекера, финальное решение за QA-инженером.
- **`tests/main-screen/non-authorized-user.spec.ts`** — автотесты, написанные
  по этим тест-кейсам (фича «Главный экран для неавторизованных пользователей»:
  публичный контент банка — баннеры, список кредитов/карт/депозитов — без
  авторизации, без секретов и персональных данных).
- **`src/`, `test-data/`, `playwright.config.ts`, `tsconfig.json`, `package.json`** —
  минимальный запускаемый срез реального проекта, достаточный именно для этого
  одного spec-файла (см. «Самостоятельный запуск» ниже). Это НЕ копия всего
  `qa-api-tests` — ужато/вручную выбрано:
  - `src/services/umbraco.service.ts` — урезан с 1061 до ~140 строк (оставлены
    только вызываемые этим файлом методы; логика лояльности/футера/карт/
    сплэш-скринов/юр.документов исключена);
  - `test-data/constants.ts` — вручную извлечённые ~95 строк из реального файла
    на 5665 строк (только использованные константы);
  - `test-data/allure-annotations.ts` — 1 из ~30 пар EPIC/STORY реального файла
    на 298 строк;
  - `@fixtures/services.fixture` (2013 строк, подключает фикстуры всех сервисов
    приложения) не используется этим файлом вообще — импорт заменён на
    `@playwright/test` напрямую;
  - `src/helpers/allure-helper.ts` и `src/models/registration.model.ts` —
    минимальные заглушки вместо полных файлов проекта (Allure-attach и типы
    регистрационного флоу этому срезу не нужны).

  В коде `test-data/constants.ts` **нет ни одного буквального значения** —
  пути Umbraco Delivery API и ID/путь конкретного элемента CMS читаются
  только из `process.env`, без дефолта в коде. Все 4
  переменные перечислены в `.env.example` только по именам; реальные значения
  живут исключительно в локальном `.env` (не коммитится, см. `.gitignore`).

## Самостоятельный запуск

```bash
npm install
cp .env.example .env   # заполните BASE_URL / UMBRACO_CMS реальными значениями стенда;
npx playwright test --reporter=list
```

## Процесс (что делегировалось агенту)

1. Установить акселератор на wrapper-воркспейс вокруг реального проекта, не
   затрагивая сам клиентский репозиторий (`.claude`/`CLAUDE.md` там уже были в
   `.gitignore` до этой задачи).
2. Прочитать требования фичи (US-3.1 бизнес-требования + техническая
   реализация Umbraco Content Delivery API).
3. Написать по ним тест-кейсы с подробными шагами.
4. Автоматизировать тест-кейсы (Playwright + TypeScript).
5. Реально прогнать автотесты против стенда.
6. Записать результат (прошло/не прошло) в файл.
7. Собрать минимальный самостоятельно запускаемый срез (по запросу — изначально
   в репозиторий попал только сам spec-файл как референс).

Коммит и пуш в этот репозиторий сделаны вручную (человеком), согласно
PUSH_POLICY=never, установленному при онбординге.
