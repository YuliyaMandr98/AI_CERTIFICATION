# AI-сертификация: Оптимизация производительности автотестов (задание 13)

Демонстрация цикла Research → Plan → Implement → Verify на двух реальных автотестах
проекта `qa-api-tests`, с помощью Claude Code. Используется тот же персональный
AI-слой (акселератор) и тот же безопасный, не связанный с авторизацией срез кода,
что и в задании 20 (ветка `task-20-micro-delegation`) — здесь к нему добавлен
анализ производительности на двух разных файлах.

## Что здесь

- **`results/performance-optimization-report.md`** — главный результат, два кейса:
  1. `tests/main-screen/non-authorized-user.spec.ts` — проверены 2 типичные
     гипотезы (setup/teardown, параллелизация), обе отклонены реальными
     цифрами; код не менялся осознанно.
  2. `tests/accounts_and_deposits/deposit-calculator.spec.ts` — найден и
     устранён реальный дублирующийся сетевой вызов (кэширование в `beforeAll`),
     но суммарный выигрыш оказался скромным — измерение показало, что доминирует
     не setup, а сам бизнес-расчёт (`calculateDeposit`, ~2.4с/вызов), который
     кэшировать нельзя.
- **`scripts/measure-setup-cost.ts`**, **`scripts/measure-deposit-calls.ts`**,
  **`scripts/measure-calculate-cost.ts`** — вспомогательные скрипты для
  изолированных замеров (RESEARCH-шаг обоих кейсов).
- **`.claude/`, `src/`, `test-data/`, `tests/main-screen/non-authorized-user.spec.ts`,
  `playwright.config.ts`, `tsconfig.json`, `package.json`, `.env.example`** —
  минимальный безопасный самостоятельно запускаемый срез (см. README ветки
  `task-20-micro-delegation` за подробностями урезания), без буквальных значений
  в коде.
- **`tests/accounts_and_deposits/deposit-calculator.spec.ts`,
  `src/services/deposits.service.ts`, `src/fixtures/deposits.fixture.ts`,
  `src/helpers/test-helpers.ts`** — второй кейс: 24 из 27 тест-кейсов реального
  файла, НЕ требующих авторизации (3 кейса из блока "Сценарии, требующие
  авторизации" исключены — нужен реальный Keycloak-логин, вне рамок безопасного
  среза). `deposits.service.ts` урезан с 2564 строк реального файла до
  используемых методов; реальные ID продуктов/валюты и пути API — в `.env`,
  без буквальных значений в коде.

## Самостоятельный запуск

```bash
npm install
cp .env.example .env   # заполните реальными значениями стенда
npx playwright test --reporter=list
```

Изолированные замеры:
```bash
npx tsx scripts/measure-setup-cost.ts
npx tsx scripts/measure-deposit-calls.ts
npx tsx scripts/measure-calculate-cost.ts
```

## Коротко об итоге

**Кейс 1 (главный экран)**: setup/teardown — 1.1% времени, параллелизация уже
даёт ~3× выигрыш и не улучшается дальше. 98.9% — сетевой round-trip. Менять
код не стали — измерения не оправдали ни одной из проверенных гипотез.

**Кейс 2 (депозитный калькулятор)**: найден реальный дублирующийся вызов
(`getProductCurrencyConditions`, ~2.3с, вызывался 23 раза с 3 уникальными
аргументами) — закэширован в `beforeAll`, 0 новых падений. Но суммарное время
прогона почти не изменилось: `calculateDeposit` сам стоит ~2.4с за вызов и
вызывается ~29 раз с разными параметрами — это и есть предмет теста, кэшировать
нечего. Оптимизация реальна и корректна, просто её эффект на фоне доминирующего
некэшируемого бизнес-расчёта оказался скромным — само по себе честный и полезный
вывод измерения, а не повод считать работу невыполненной.
